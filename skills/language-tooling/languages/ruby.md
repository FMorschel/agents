# Ruby (includes Rails)

Use the project's Bundler (`bundle exec ...`) to run any tool, so the versions in `Gemfile.lock` apply. In Rails, the tasks live in `bin/rails` and `bin/rake`. Below, the default when the project defines nothing.

## Static analysis and compilation

- Lint: `bundle exec rubocop` (configuration in `.rubocop.yml`, with chained `inherit_from`/`inherit_gem`). Types, when the project uses them: Sorbet (`bundle exec srb tc`) or Steep.
- Ruby does not compile before running: "compiles" means a syntax check (`ruby -c file.rb`), no new RuboCop offenses and the file loading (`bundle exec ruby -e 'require "./lib/x"'`; in Rails, `bin/rails runner 'puts 1'`).

## Formatting and automatic fixes

- RuboCop also formats: `bundle exec rubocop -a <files>` (safe fixes) and `-A` (includes the unsafe ones; review the diff). Some projects use `standardrb` (`bundle exec standardrb --fix`) or `syntax_tree`.
- Suggested post-edit order: `rubocop -a` → types (if any) → tests.

## Checking without changing files

For a review, which never writes: `bundle exec rubocop` **without** `-a`/`-A`, `bundle exec srb tc` (if any) and `bundle exec rspec` / `bin/rails test`. Never `rubocop -a`/`-A`, `standardrb --fix`, nor `bundle install`/`update` (they change `Gemfile.lock`).

## Tests and coverage

- RSpec (`bundle exec rspec`) or Minitest (`bin/rails test`, `bundle exec rake test`). A single file or example: `rspec spec/x_spec.rb:42`, `rspec -e "text"`, `bin/rails test test/x_test.rb:42`. By tag: `rspec --tag slow`, `--tag ~slow` to exclude.
- How to write: `write-dart-tests` (general rules).
- `*_spec.rb` files in `spec/` (or `*_test.rb` in `test/`) mirroring `lib/`/`app/`: copy what the project does.
- Coverage: SimpleCov (`require "simplecov"` at the top of `spec_helper.rb`/`test_helper.rb`; report in `coverage/`).
- Exception: `expect { f("") }.to raise_error(ArgumentError, /empty/)`; Minitest: `assert_raises(ArgumentError) { f("") }`. Then check the state.
- Time: `travel_to` (ActiveSupport) or `Timecop`; inject the clock when possible.
- `git stash push -- <production files>` serves for the red → green proof.

## Manifest, lockfile and dependencies

- `Gemfile` and `Gemfile.lock` (for gems: `*.gemspec`); `bundle install`, `bundle add`.
- `Gemfile.lock` goes with the `Gemfile` change in the same commit. Ruby version in `.ruby-version` or in the `Gemfile`.

## Generated files

- `db/schema.rb` and `db/structure.sql` (generated by migrations: do not edit by hand, and version them with the migration that changes them), `Gemfile.lock`, Sorbet/Tapioca `*.rbi` (`sorbet/rbi/`), `public/assets/`, `node_modules/` and `tmp/`, `log/`, `coverage/` (not versioned).
- Regeneration: `bin/rails db:migrate`, `bundle exec tapioca gems`, etc.
- It stays out of coverage (SimpleCov `add_filter`) and of style inference.

## Doc comments, references and TODO

- `#` comments above the declaration, in YARD format: `@param name [Type] description`, `@return [Type]`, `@raise [Error]`, `@example`. The first line is the summary. Symbol reference: `{Class#method}` (instance) and `{Class.method}` (class). RDoc is the alternative, if the project uses it.
- `# TODO(name): ...`.

## Suppressing a lint or a type error

- `# rubocop:disable Cop/Name` (and `# rubocop:enable` right after, or on the same line at its end), `# rubocop:todo`; a whole file in `.rubocop_todo.yml`.
- Sorbet: `# typed: false`/`T.unsafe(x)`.

## Nulls

- No null safety: `nil` is an object. Avoid it with `x&.method` (safe navigation), `x || default`, `x.nil?`, `fetch` on a hash (fails on a missing key) and `Array(x)`.
- There is no assertion `!`; the closest is `raise ArgumentError, "reason" if x.nil?` or `fetch`.

## Script output

- `$stdout.sync = true` at the start (or `$stdout.flush` after `print 'text ... '`) so the text appears before slow work; errors on `warn`/`$stderr.puts`.
- Child process: `system(cmd, *args)` inherits the terminal; avoid backticks and `Open3.capture*` when the user must see the output live.

## Post-edit flow

There is no dedicated skill. Run, in this order: RuboCop with auto-correct, types (if the project uses them), the file's tests and then the full suite, via `bundle exec`.
