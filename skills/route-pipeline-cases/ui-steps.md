# UI steps: catalog, surface and visual review

**Widget catalog.** A step that adds or changes a public widget or screen carries, where the project keeps a catalog, its `@Preview` (when the project already uses them) and its Widgetbook use cases (when the project depends on `widgetbook`), in its `Done when` (`step-planner` puts them there, per `catalog-flutter-widgets`); `tester` writes the use cases and state builders in `F`, `implementer` the `@Preview` in `G`. Only widgets this run adds or changes count: existing widgets without entries are never findings, including in the run that adds Widgetbook. When no package depends on `widgetbook` yet, the proposal to set one up is raised **once per run**, as an unrequested extra in the plan the human skims; until they say yes, steps add only the state builders (and an `@Preview` where the project already uses them); a catalog is never introduced just for testing, and the missing use cases go in the final report as one line, not as a finding per step.

`ui-surface-agent` (which follows the `check-ui-surface` skill; for a whole-app check use `sweep-app-for-ui-pattern`) gets only the current step's plan (from `step-planner`) — never the tester's tests or the implementer's diff, since it runs before either exists for that step. It only runs at all when the step touches UI surface (`R`); skip it entirely for backend/logic-only steps rather than calling it and expecting a no-op report.

`flutter-visual-reviewer` is separate and optional: after `implementer` finishes a step that changes how a widget or screen looks or lays out, and a debug app is reachable over DTD, it can check the live result before and after (see `review-flutter-visual-changes`). It needs the step's changed files and target screens, nothing else. Because it stashes the working tree for its baseline, run it alone (nothing else editing the tree) and only with human agreement; in autonomous mode, skip it and flag the step as "visual check pending" in the report. Its regressions and visual bugs are blocking: route back to `implementer`. Missing golden or widget tests and missing Widgetbook use cases it reports go to `tester` (per `write-flutter-ui-tests` and `catalog-flutter-widgets`); a missing `@Preview` goes to `implementer`.
